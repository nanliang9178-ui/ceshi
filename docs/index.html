功能全景

一台扫码点单，把店里的活都干了

从顾客扫码到老板出餐，全链路闭环。每个模块都落在真实业务里，不是展示用的花瓶。

扫码直接点单

扫普通二维码，手机浏览器直接打开点单页，自动识别桌号。不需要小程序、不需要公众号、不需要审核，桌码后台实时生成。

堂食 / 外卖双模式

外卖含收货人、手机号、详细地址校验、配送费、起送价与预计送达时间；堂食自动带桌号，两种模式同一界面切换。

商户后台工作台

订单、菜品、桌码、统计、品牌、支付、员工权限一屏管理。电脑看完整后台，手机打开自动进入「老板台」。

手机版老板台

只保留「今日盈利 / 待做订单 / 我的菜品」三块，手机上接单、出餐、一键估清，不用抱着电脑跑。

白标交付换肤

上传 logo、头图、轮播，选主题色与标语，保存即生效。小程序所有颜色走 CSS 变量 —— 后台改色，整体焕新。

微信支付 v3 JSAPI

商户自有商户号收款，平台不触碰资金；回调验签解密、幂等入账、原路退款。未配置时自动走演示支付，不卡下单。

实时新单推送

Socket.IO 实时推单 + 语音提示音，断线自动轮询兜底。订单状态机：待支付 → 待接单 → 制作中 → 待取餐 → 已完成。

经营看板

营业额趋势、时段分布、品类占比、热销榜。改价、退款、支付配置变更全部写审计日志，可追溯。

多租户与安全

商户间数据严格隔离；服务端强制重算价格，下单幂等防重复；敏感配置 AES-256-GCM 加密落库，接口永不回显明文。

快速开始

3 步跑起来

环境要求 Node.js ≥ 18.18（推荐 20/22）。默认 SQLite，不需要安装数据库。

# 1. 安装依赖 + 建库 + 初始化演示数据
$ npm install
$ npm run setup

# 2. 启动后端（终端 A）
$ npm run dev:api

# 3. 启动管理后台（终端 B）
$ npm run dev:admin

→ 老板台 http://localhost:5173/boss

→ API http://localhost:3000/api

白标交付

一套代码，交付 N 个品牌

这是这套系统真正的商业价值：不用为每家商户重写一遍，交付成本从「开发一个项目」降到「改一套配置」。

01 · 运行时换装

后台改，立刻生效

上传 logo、门店头图、首页轮播，选主题色与辅助色（右侧手机实时预览），填写品牌标语、公告、客服电话。保存后下次启动即拉取新配置，无需发版。

02 · 独立发布

一商户一主体

复制小程序目录，改 utils/env.ts 里的 API 域名与商户编码，配好白名单提交审核即可。平台后台「开通商户」会生成唯一商户编码。

03 · 聚合模式

一个平台服务多商户

小程序码 scene 携带桌位编码，后端据此解析商户 —— 顾客扫谁的桌码就进谁的店，无需为每个商户单独发版。
